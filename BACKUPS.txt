Growing Grounds automatic backups

Windows
Install the complete GG archive, including tools/ and backup/. No Python
installation, admin account, scheduled task or alternate game shortcut is needed.
The Lua mod arms the private companion once at startup. The companion sleeps
on the owning game process; it does not scan, copy, hash or compress saves while
that process is running. On clean exit it waits120 seconds, then archives at
background CPU/I/O priority. A new GG launch cancels pending/in-progress work
and waits for its file handles to close before initialization continues.
The worker also checks for a new Palworld process while it works, to stop before
that process reaches the mod. No zero-cost or measured-FPS claim is made.

The first Windows archive is a protected baseline AFTER the first clean exit.
It is not a pre-install backup. Keep a separate world backup before installing
or updating a mod. A crash, forced stop or computer shutdown does not create a
new archive. A dedicated server that never stops has no new GG checkpoints;
Palworld's own backups remain unchanged.

Normal solo/co-op saves: %LOCALAPPDATA%\Pal\Saved\SaveGames
Dedicated saves: Pal\Saved\SaveGames in that server installation.
Archives: GrowingGroundsBackups beside SaveGames.
Status: GrowingGroundsBackupState\status.json beside SaveGames.
A joining client's LocalData.sav cache is not a full world and is excluded.
Global Palbox storage outside the selected worlds is not included.

Proton/Linux — one-time setup
Python 3.9+ and a working user systemd session are required. Use the shipped
setup tool with the actual SaveGames directory in your Proton prefix:

python3 tools/backup_setup.py --save-root '/actual/prefix/drive_c/users/steamuser/AppData/Local/Pal/Saved/SaveGames'

It prints a Steam launch-options line ending in %command%. Paste that line into
Palworld's launch options. The generated launcher forwards the original game
command and environment. Keep your MangoHud/other launch wrappers around the
original command as needed; no graphics or game settings are changed.
For a dedicated server, run the generated gg-launch followed by its usual
server command instead. A profile must own its save folder: use that launcher
for every process that writes those saves. The generated files stay beside
SaveGames; neither game executables nor existing worlds are modified by setup.

This launcher first cancels any pending backup, protects missing initial
baselines BEFORE starting the game, then holds the session lock until exit.
After a clean exit a separate user timer waits120 seconds and runs the archive
worker. A quick restart cancels that worker before the game starts. The worker
uses idle I/O priority, nice 19, a 20% CPU quota and a 256 MiB memory limit.
If an initial baseline cannot be created, the protected launch reports that
failure instead of pretending the world is protected. Remove the launch option
to launch without GG backups. No archive is made during a managed session.
An unmanaged launch cannot provide the same lock guarantee.

Retention and disk space
All worlds under one SaveGames installation share a hard1 GiB archive-directory
budget, including temporary archives. The policy also leaves1 GiB of free disk
space. It keeps the original baseline, the most recent three rolling copies,
and one per previous day for seven days. Copies serving two categories are
not duplicated. It skips unchanged saves and applies a 30-minute cooldown that
survives restarts. A backwards clock skips work instead of bypassing cooldown.

Verified older history may be removed to make room, but every baseline and the
latest verified copy of every world are protected. If a new complete archive
cannot fit alongside those protected copies, it is skipped with storage-limit
in status.json. Unrecognized/corrupt files are never deleted automatically and
count against the budget. Native Palworld backup/ rotations are excluded from
GG archives and are not included in this GG-only1 GiB limit.

Archive and restore
Each ZIP contains the complete authoritative world (including Players), GG
config.lua and world-settings.ini if present, plus a manifest with world ID,
UTC creation time, mod version, sizes and SHA256 hashes. Source inventory and
bytes are checked for changes; archive contents are verified before a unique
atomic publication. A cancellation discards its incomplete .partial file.
A machine/power failure may leave a .partial file; it counts toward the cap and
is never offered as a completed backup. Hashes detect corruption, not authorship.
Archives are local; no uploads or network calls occur in the runtime companion.

On Windows, use the included interpreter from the installed mod directory:
backup\python\python.exe tools\save_backup.py verify ARCHIVE.zip
backup\python\python.exe tools\save_backup.py restore-copy ARCHIVE.zip NEW_FOLDER

On Linux use python3 in place of backup\python\python.exe. Restore-copy verifies
and writes a NEW review folder. It never replaces a live save or runs Lua config.
Stop the game/server, preserve its current save, then restore the reviewed world
and matching settings. This rolls player/world progress back together. Keep GG
installed when loading Pals in extra Palbox boxes. RESTORE-INCOMPLETE.txt means
the restore did not finish and must not be used. Keep an independent backup if
you also need protection from drive failure.

Disable/remove
Windows: automaticBackups=false in config.lua stops arming the companion at the
next launch. Let an existing session close and its pending worker finish first.
Proton/Linux: remove the generated Steam launch option/server wrapper. Do not
remove GG files while a backup worker is active. Existing ZIPs are retained
when the mod is removed. The small lock file is deliberately left in place;
never delete it to bypass a lock.

Build and validation
The embedded CPython 3.14.10 x64 archive is pinned to Python.org's release SHA256.
Its license and runtime-provenance.json ship with GG. There is no system-wide
installation and the interpreter ignores ambient Python packages.
Build once: python3 tools/backup_runtime.py --fetch
Package: python3 tools/release.py
Tests: python3 -m unittest discover -s tests -p 'test*backup*.py' -v
Windows lifecycle fixture: tests/windows_backup_smoke.py (disposable paths only).
The fixture under Wine proves Win32 process/cancellation/file handling, not a
physical Windows Steam installation. That remains part of release validation.
