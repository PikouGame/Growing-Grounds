Growing Grounds 0.2.0-beta — internal mod ID BaseRangeGrowth

Install or update
1. Save and close the game/server, and back up your world.
2. Install a compatible Palworld UE4SS loader once on host/server and clients.
   It must support ExecuteInGameThreadWithDelay and LoopInGameThreadWithDelay
   (available in the tested Palworld fork 2281fa31).
3. Copy BaseRangeGrowth into the existing UE4SS Mods folder on both sides:
   Manual: Pal/Binaries/Win64/ue4ss/Mods/BaseRangeGrowth
   Existing Workshop loader: Mods/NativeMods/UE4SS/Mods/BaseRangeGrowth
   Use your existing loader location; do not install a second loader.
4. Preserve your config.lua preferences and world-settings.ini / .bak files.
   Add new defaults as needed. Never replace your sidecar with another player's.
5. Restart host/server and clients. Allow up to five seconds for the initial UI.

Updating from 0.1.1 or older can shrink bases because of the cap and spacing
limits. Buildings outside the resulting boundary may lose coverage. Keep a backup.
0.1.3 does not change those gameplay rules. It removes development keyboard
shortcuts entirely; an old debug=true option is ignored. No test hotkey is needed.

Unreleased development update: independent growthPercentPerLevel is restored
alongside the maximum bonus. Existing values are used within 0..20%; a missing
value defaults to 4%, and 0 keeps range growth off. Unlike published 0.2.0-beta,
the cap is no longer spread across all base levels. With a 35m base and defaults,
level 11 is 49m (+40%) and level 26 reaches 70m (+100%). Review both settings
before loading an existing world: changing either may change its current
boundary, subject to nearby-base limits. Keep a separate backup before updating.
The new range controls and starting/total Palbox settings still need native-game
validation. Install matching development versions on host/server and clients.
Bonus chest caps now use 0, 6, 12, 18, 24, 30, 36 or 42; default 18. Existing
caps round to the nearest step (20 -> 18, 40 -> 42). Occupied extra slots remain
until emptied. Update host/server and clients together for the new 42-slot cap.
Updating from 0.1.6 or older: bonus chest slots are spread over all base levels,
so existing chests follow that schedule at once (level 11: 10 bonus slots become
5 with the default 18-slot cap). Extra slots that hold items stay until emptied; nothing is deleted or moved.

Configuration
- growthPercentPerLevel=4: independent radius bonus per base upgrade (0..20%).
  0 disables range growth without erasing the cap. Rewards round to whole percent.
- maxRangeBonusPercent=100: maximum radius BONUS (0..300%). +100% doubles radius.
  Growth stops at this cap. A low gain may never reach it at the last base level.
  0 disables range growth without changing the per-level gain.
  Legacy maxRangePercent totals retain their previous conversion/clamp.
- maxChestBonusSlots=18: bonus chest slots at the last base level, spread evenly
  over all levels (with 18: 1 at level 2, 5 at level 10, 18 at level 35).
  Bonus limit 0..42 in steps of 6; other values round to the nearest step. Guild Chests share one bonus for the whole guild.
  Lower limits retain occupied overflow slots until they are emptied.
- startingPalboxBoxes=32: TOTAL boxes at base level 1, minimum 1, maximum 96.
- maxPalboxBoxes=64: TOTAL boxes at the final base level, including starting boxes.
  Limit 1..96; start is lowered to the maximum if larger. Whole boxes are spread
  across all base levels. Example: start 1 / maximum 16 gives 1 at level 1,
  9 at level 18 and 16 at level 35. Equal values give a fixed capacity.
  Legacy maxPalboxBonusPages migrates to start 32 / total 32 + old bonus unless
  an explicit maxPalboxBoxes is present. The old +1-per-upgrade rule is replaced.
  Each player follows their guild level once; extra bases do not multiply it.
  Global Palbox storage is unchanged. Occupied/locked/open boxes are retained.
- resetToVanilla=false: see removal instructions before changing this.
- upgradeAnimation=true: enables the automatic upgrade celebration.
- upgradeRibbon=true: enables glow effects; false disables both wave and rise.
- upgradeWave=true: enables the Palbox-to-boundary ground wave.
- upgradeEffectHeight=600: rise height in centimetres (clamped to 100..2000).


Local/co-op hosts can change the range gain/cap, chest cap and Palbox starting/total
counts beside native base/building controls in custom World Settings. Values save per world after native confirmation, in world-settings.ini.
Dedicated servers use config.lua defaults unless that host has a per-world
sidecar override. Server settings always control gameplay and the next-value UI.

With the standard 35m radius and the default cap: level 8 = 44.8m, level 11 =
49m, level 26 = 70m, level 35 = 70m. Each level's bonus is a whole percent
of the original radius. The UI shows the bonus above 100%, with metres rounded to a
tenth. Level 10 displays 26% 44.1m -> 29% 45.2m. At maximum game level, the next
value is hidden. On a client, while the server's preview
is missing or out of date, Base Upgrade keeps its last complete Growing Grounds values,
or shows no Growing Grounds row on a first open.

Spacing and server authority
New Palboxes reserve two maximum radii (140m by default), across guilds and
heights, for PvE and PvP. Stronger native restrictions remain. Existing nearby
bases share free growth space and may reach a lower cap. Originally overlapping
circles receive no extra growth. Bases are never moved or deleted.
Clients read the server radius; only the visible boundary bounces. One invisible,
non-ticking native component per Palbox carries the server's next-value preview
through its existing network channel. No added ports, chat messages or save models.
Temporary raid bases, decay, spawning and unrelated collisions are untouched.

Animation
A 2.4s blue wave follows sampled ground from the Palbox to the old boundary,
then triggers the expansion/bounce. Once settled, a contour rises, gradually
softens sharp relief, brightens and fades with its trail while still moving.
Preparation starts after a confirmed upgrade. It stays hidden while the matching
Base Upgrade screen is open and plays when the screen closes and setup is ready.
There is no fixed countdown or terrain cache between animations. The celebration
can still start late; the actual gameplay radius is already updated.
Fresh terrain work is bounded to 64 samples and a shared 3ms deadline per update.
Native calls cannot be interrupted, so this is not a hitch-free guarantee.
The effect uses one procedural mesh and a native glow material; no moving mesh
rebuilds, repeated ground scans during playback or speculative idle scans.

Remove/reset
Expanded radii can be saved by the game, and enlarged chests are: deleting the mod
alone leaves each chest at its enlarged size, with its items in place. To return the
world to its original sizes first, set resetToVanilla=true on the SERVER, restart and
load the world. Radii go back to the original. Each chest goes back to its native
size; stacks sitting above it are first moved into free native slots, in the same
order. A chest holding more stacks than its native size keeps the slots in use:
UE4SS.log names it ("ItemChest_02 keeps 30 slots instead of 24 until the slots above
are emptied") and it shrinks once you empty them. Occupied slots are never removed.
The "reset complete: N chests at native size" message covers chests only.
Before removing GG, each player must also join with reset enabled and move
all Pals out of bonus Palbox boxes into the original boxes, then close the
Palbox. Offline players are not checked by an online player’s reset.
Keep GG installed until every player has cleared those boxes and their original
box count has returned. Save, then remove BaseRangeGrowth on both sides. "reset waiting" means a chest still has to be
emptied; the last reset line is the current state.
Buildings in the added area may lose coverage. An exact rollback requires the
pre-install world backup, which also rolls back progress since that backup.

Compatibility and verification
The new Palbox starting/total-cap progression is an unreleased development change.
Its native replication, smaller starting sizes and save/reload are NOT VERIFIED
yet; test it on a world copy. The previous 0.2.0-beta expansion was checked in
solo and dedicated-server sessions. Update server and clients together; an older
client cannot display the new total-cap preview.
Inspected Palworld v1.0.5.102999; client Steam build 25246127, server 25247047;
UE4SS Palworld fork 2281fa31. Windows executables were tested through Proton/Wine.
Native Windows OS execution and Workshop deployment are not verified.
The UI and radius replication were observed in game. Standalone checks cover
settings, spacing, authority, preview, UI layout and animation lifecycle.
Chest growth, save/reload, client item transfers, occupied-slot protection across
a restart, empty-slot removal and garbage collection were checked natively.
World Settings rows were checked in the normal new-world menu, then cancelled.
An earlier intermittent client crash remains unattributed; this release is not
claimed to fix it. Saving World Settings, starting a new world, placement
rejection, expanded-area Pal work/resources,
full removal/reset and other range mods still need broader live testing.

Replacing a build with GG automatic backups
The backup companion is archived and no longer included. The mod does not
create new GG archives. Palworld's native backups remain unchanged.

Close the game/server and let any pending old archive finish. If Proton/Linux
used the GG gg-launch wrapper, remove ONLY that wrapper from Steam launch
options or the server launch command; preserve other launch options.
Keep config.lua and world-settings.ini / .bak, then replace the old
BaseRangeGrowth folder with the new one instead of merging folders. Restore
your saved settings. The old automaticBackups key is ignored and may be removed.
Do not copy back tools/, backup/, backup-version.txt or src/backups.lua.
Keep existing GrowingGroundsBackups archives and any custom archive directory.
The archived source and restore-tool reference are in ARCHIVED-BACKUPS.txt
in the source repository.
